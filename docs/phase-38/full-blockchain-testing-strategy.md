# Phase 38 — Full Blockchain Testing Strategy

## Purpose

Validate the full blockchain proof lifecycle before production readiness, business demo preparation, final audit reporting, and final deployment.

## Core Principles

1. PostgreSQL remains the source of truth.
2. Blockchain stores proof records only.
3. No PII or sensitive business data is stored on-chain.
4. Hash generation must be stable and repeatable.
5. Proof submission must be retry-safe.
6. Verification must detect matches, mismatches, and missing proofs.
7. Invalid records must not be silently activated.
8. Compliance rules must be auditable.
9. Bulk approvals must be logged and provable.
10. Validation must be repeatable.

## Test Scope

| Area | Coverage |
|---|---|
| Functional testing | Backend services, routes, controllers, and UI entry points |
| Hash stability | Same data same hash, changed data different hash |
| Blockchain key stability | Valid keys are normalized and validated |
| Proof submission | Proof payload can be submitted through backend and Fabric |
| Proof verification | Proof can be read and verified |
| Tamper detection | Modified source data produces mismatch |
| Invalid record review | Invalid changes enter review workflow |
| Compliance proof rules | Allowed and sensitive changes follow rules |
| Auto approval | Low-risk changes can be auto-approved |
| Manual approval | Sensitive changes require manual approval |
| Bulk approval | Large change sets are logged and provable |
| Batch proof | Batch and Merkle proof logic can be verified |
| Retry/failure handling | Failed submissions remain recoverable |
| Privacy | On-chain payload excludes raw business data and PII |
| Dashboard | Verification, mismatch, review, and proof screens are covered |
| Export report | Audit evidence can be exported |
| Performance | Indexes and proof workflows are suitable for audit volume |
| End-to-end demo | CEO, Compliance, and Audit demo can be executed |

## Pass Criteria

Phase 38 passes when all validation commands pass, the Fabric SDK reaches the deployed chaincode, proof-related chaincode tests pass, and repeatable evidence is saved under inspection-output.
